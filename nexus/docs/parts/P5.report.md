What the tests pin down:

- **A4.** Provider `alpha` answers HTTP 429 with `Retry-After: 45`, and `beta` answers instead. The notes are exactly
  `["alpha: rate limited (HTTP 429), cooling down 45 s", "answered by beta"]`. The next call
  skips alpha (`model.refused` COOLING_DOWN) without sending it anything. Once the clock passes 45 s,
  alpha is tried again and answers.

  With a 503 from alpha and connection refused from beta, the local model answers, and
  each failure has a note. When every provider fails, the result is
  `ModelError("NO_PROVIDER")` with all the notes.
- **A5.**
  - Replies of "not json", then `{"answer": ""}`, then `[1]` give exactly 3 requests, then
    `OUTPUT_INVALID` with "alpha gave no schema-valid reply in 3 attempts". Beta is never asked.
  - Each retry shows the model its own reply and the validation error.
  - A retry that fixes the output succeeds; a JSON code fence around the reply is accepted.
- **A6.** Five configurations of a paid provider all give `model.refused` BUDGET_EXCEEDED, and
  the paid endpoint receives **zero** requests:
  - the default daily budget of 0;
  - the per-request budget of 0;
  - an estimate over the request budget;
  - an estimate over the daily budget (refused by the ledger);
  - a provider with no prices.

  Given a real budget, a paid call records `cost_usd` = 27 tokens × $100/Mtok = $0.0027 in the
  event and in `model_usage`, with nothing left reserved.

  **Concurrency:** 20 concurrent calls against a cap of 5/day give exactly 5 requests and 15
  DAILY_REQUEST_CAP refusals. The next UTC day the cap resets.
- **A7.** `private=True` gives PRIVATE_DATA refusals for gemini-kind and openai-kind providers, and
  the local model answers. With the local model down, the result is NO_PROVIDER. In both cases
  the cloud providers receive no request.
- **A8.**
  - Six requests produce six `model.called` events, all on `session/<id>`.
  - A provider error body that echoes the key is stored as `HTTP 401: API key [redacted] invalid`.
    No key string appears anywhere in the event JSON.
  - Each event carries `call_id`, provider, model, attempt, outcome, tokens, cost, latency and
    `prompt_sha256`, plus the output when it is valid.
  - `verify_chain` reports intact.

## 1a. Live check with the owner's Gemini key (opt-in, by hand)

The key came from the git-ignored `../.env.keys`. It was set only in the command's environment
and never printed or written. Every prompt was the public "What is the capital of France?".
In all, 8 Gemini requests were made, at $0.

1. **`gemini-2.5-flash`** (the first default) answered `HTTP 404: This model models/gemini-2.5-flash
   is no longer available to new users`. The router recorded `error` and failed with NO_PROVIDER.
   The model list from Google's models endpoint (which uses no generation quota) shows current
   names and the aliases `gemini-flash-latest` and `gemini-flash-lite-latest`.
2. **`gemini-flash-latest`** answered once ("Paris", 66+6 tokens, 4072 ms). The next four calls got
   a read timeout at the 20 s `timeout_s` three times, then `HTTP 503: This model is currently
   experiencing high demand`. Each time the router recorded `unavailable`, cooled the provider
   down for 60 s, spent nothing, and failed cleanly.
3. **`gemini-flash-lite-latest`** answered every call:

## 2. Deviations from the brief

- **D1. `nexus-ci.yml` changed** (the one allowed file outside `nexus/`). Both pytest steps now
  exclude `live`. The validate step also covers `src/nexus_packs`, so it matches
  `make validate`; that P4 change had not been carried over to CI.
- **D2. The canned provider responses are hand-written**, in the format each provider documents.
  They are not recordings: none could be made without spending a key's quota from CI. The
  parsers fail closed, so if a real format differs the provider gives `error` and the router
  fails over. `make test-live` checks the real formats.
- **D3. Refusals other than budget are events too** (NO_KEY, PRIVATE_DATA, COOLING_DOWN,
  DAILY_REQUEST_CAP). The blueprint only asks for budget refusals, but these make every
  failover explainable from the log.

## 3. Design notes worth reviewing

1. **Data use on free tiers.** Gemini's free tier may use what it receives to improve Google's
   products. **Send no private data through it**: plant data, personal data, anything under NDA.
   The router enforces this only when the caller passes `private=True`. P6 must set that flag
   for anything that is not public. Groq is also `private_ok: false` until its terms are checked.
   Only the local Ollama model receives private requests.
2. **The usage ledger can over-count after a crash, never under-count** (ADR-0015, consequences).
   It guards budgets; the events are the record.
3. **Token estimates are rough**: characters / 4, plus all of `max_output_tokens`. A budgeted
   paid call needs room for the worst case. A test hit exactly this: with the default 1024 output
   tokens at $100/Mtok, the estimate is about $0.11, so a $0.10 request budget refused it.
4. **Cooldowns are per process, in memory.** They are enough for one API server. Several
   workers each learn about a 429 separately.
5. **Prompts are stored as a SHA-256 only.** P6 decides what a plan's evidence must keep.
6. **Model names in `models.yaml`.** Gemini now uses the alias `gemini-flash-lite-latest`
   (see §1a). `llama-3.3-70b-versatile`, `llama3.2` and the daily caps (200 and 500) are still
   unchecked defaults. `nexus models` shows what is configured.
