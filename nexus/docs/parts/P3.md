# P3 — Executor, verifier, compensation

**Status:** built, awaiting review (see `P3.report.md`) · **Estimate:** 1–2 weeks · **Milestone:** M1 (4 of 5 parts)
**Read first:** `../../GOAL.md`, `../INDUSTRIAL_BLUEPRINT.md` §4.5–4.7, `P2.md`, ADR-0008,
ADR-0010 (self-compensation), ADR-0012 (execution), ADR-0013 (approvals).

## Goal

Turn a decision into at most one execution: approved where it must be, re-checked against fresh
state, run through the pack's binding with a timeout, verified against the action's effects, and
compensated with an incident when anything goes wrong. Shadow mode decides and records but never
calls a binding.

P3 contains **no real connector (a mock binding only), no HTTP, no evidence pack or `nexus trace`
(P4), no autonomy promotion or demotion, and no LLM**.

---

## 0. Hard constraints

The P0–P2 constraints all still apply. In addition:

1. **At most once.** One idempotency key executes at most once, across retries, duplicate
   submissions and concurrent callers. The claim is a database row, not a check in memory.
2. **Fail closed.** No execution without an ALLOW, or a NEEDS_APPROVAL with enough valid
   approvals, and a re-check at execution time that is not DENY. A decision that cannot be found
   or parsed is refused.
3. **Nothing undone twice.** A compensation is never compensated (ADR-0010). If it fails, an
   incident is opened and the executor stops.
4. **Read-only means read-only.** With the kill switch on, nothing reaches a binding, compensation
   included; an incident records what was left undone (ADR-0012).
5. **No new runtime dependency.**

The action contract gains optional `timeout_s` (1–600, default 30). The CLI gains
`nexus approve DECISION_ID --proposal-hash HASH` and `nexus reject DECISION_ID --reason TEXT`.

## 2. Binding

```python
class Binding(Protocol):
    async def execute(self, request: ExecRequest) -> None: ...  # raises BindingError on failure
    async def observe(self) -> Mapping[str, Any]: ...  # current observable values
```

`ExecRequest(action, params, idempotency_key, compensation: bool)`. The executor writes what
`observe()` returns into world state (entity = pack id, actor `pack:<id>`, stream `pack/<id>`),
keeping only keys that match a declared observable and have the declared type.

## 3. Approvals (ADR-0013)

`approval.granted` / `approval.rejected` events on the decision's session stream, payload
`{decision_id, proposal_hash, approver, approved_at | reason}`. An approval is accepted only if:
the decision exists and is NEEDS_APPROVAL; `proposal_hash` equals the decision's; the approver
is a `human`; the approver is not the proposer; the approver has not already approved it; it was
not rejected; it has not already executed. Distinct approvers are counted against
`approvals_required`.

## 4. Execution

`await executor.run(decision_id) -> ExecutionRecord`, in this order:

| # | Step | On failure |
|---|---|---|
| 1 | Find the decision; outcome ALLOW, or NEEDS_APPROVAL with enough approvals and no rejection | refused `NOT_APPROVED` / `DENIED` / `REJECTED` / `UNKNOWN_DECISION` (event `execution.refused`) |
| 2 | Claim the idempotency key (`proposal.idempotency_key`, else the proposal id): insert into `executions` and append `execution.started`, one transaction | already claimed → return that record, `duplicate=True`, nothing runs |
| 3 | Re-check: `evaluate` again on a fresh snapshot (rate limit excluded, it was applied at decision time) | DENY → `execution.refused` with the gate's reasons |
| 4 | Shadow mode: append `execution.shadowed` and stop | — |
| 5 | Capture `prev` (the pack's visible state), call `binding.execute` with `timeout_s` | error or timeout → step 7 |
| 6 | Verify: until `verify_within_s`, `observe()`, write state, evaluate every effect over `state`, `params`, `prev` | false / error at the deadline → step 7 |
| 7 | Compensate if declared: params are CEL over `params` and `prev`, validated against the compensation action's schema, executed with `compensation=True`, verified the same way | failure, or kill switch on → incident `compensation_failed` / `compensation_blocked`; never compensated again |
| 8 | Open an incident for every failure (`incident.opened`) and record the final status | — |

Statuses: `refused`, `shadowed`, `succeeded`, `failed` (no compensation declared),
`compensated`, `compensation_failed`. Every step is an event on the session stream; the
`executions` row is updated in the same transaction as the event that changes it.

Shadow comparison: `executor.record_human(decision_id, outcome, actor)` appends
`shadow.compared {decision_id, gate_outcome, human_outcome, agree}`.
