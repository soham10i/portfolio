## 2. Deviations from the brief

- **D1. Two extra refusal codes.**
  - `NO_BINDING`: the action's pack has no binding loaded, so the executor refuses before
    claiming.
  - `RECHECK_DENIED`: a refusal at re-check. It always comes first, followed by the gate's own
    codes, so a caller can tell "denied at decision time" (`DENIED`) from "denied at execution
    time".
- **D2. A refusal at re-check is final for that idempotency key.** The key was already claimed,
  so running the decision again returns the refused record (`duplicate=True`). Turning the kill
  switch off does not revive it. Acting again needs a fresh proposal. A refusal at step 1 (not
  yet approved, denied, unknown) claims nothing, so approvals can still arrive.
- **D3. The re-check refuses an ALLOW that has turned into NEEDS_APPROVAL.** This happens when
  the gate now needs more approvals than the execution has, for example after a restart with a
  tighter policy cap. The code is `NOT_APPROVED`. The brief only said "not DENY". This is the
  fail-closed reading.
- **D4. A compensation blocked by the kill switch ends as `compensation_failed`.** There is no
  seventh status. The incident kind, `compensation_blocked`, tells the two cases apart.
- **D5. Verification statuses.**
  - `failed`: an effect evaluated to false at the deadline.
  - `timed_out`: no observation succeeded, or an effect could not be evaluated (for example, a
    key with no value).
  - `not_run`: the action declares no effects (allowed for L2). It counts as success.
- **D6. Only changed observations are written.** Each poll, the executor writes an observable to
  state only when its value differs from the stored one. That avoids an event every 50–500 ms
  while polling. "Every observation is an event" therefore holds for changes. The observed
  values used are recorded in `execution.verified`.
- **D7. Small API changes in P2 code.**
  - `Gate._snapshot` is now the public `Gate.snapshot(…, rate_limit=True)`.
  - `Gate.recheck(proposal)` returns `(verdict, snapshot)`.
  - `evaluate._visible_state` is now `visible_state`.
  - `cel.from_cel` converts CEL results such as compensation params back to JSON.

  No P2 behaviour changed, and all P2 tests pass unchanged.

## 3. Design notes worth reviewing

1. **The idempotency key is global, not per session.** It is `proposal.idempotency_key`, or the
   proposal id if that is missing. Two sessions that reuse a key share one execution. This is
   what "two proposals sharing a key → once" requires, but it means keys must be unique per
   intent.
2. **A compensation bypasses the envelope.** It is not gated (ADR-0012 §5), so its params, such
   as "set level back to `prev`", are only schema-validated. If `prev` was outside today's
   envelope, the compensation still restores it. That is the point of a rollback, but please
   confirm.
3. **Any human may reject, including the proposer.** Rejecting is always the safe direction.
   Approving is limited to someone other than the proposer.
4. **A crash after the claim leaves a `running` row.** The binding is called outside any
   transaction, so a process that dies mid-run leaves the row at `running`. Recovering it is P8
   work, as the brief says. Until then, running the decision again returns that row and does
   not execute.
5. **No authentication yet (ADR-0013).** `nexus approve` takes the identity from `NEXUS_ACTOR`
   or the login name. The event chain records who claimed what.

## 5. Open questions added

- **Q-P3-1.** Should a compensation be checked against the envelope, and should it be refused if
  outside? Today the answer is no (note 2).
- **Q-P3-2.** Should a refusal at re-check release the idempotency key, so the same decision can
  run once the kill switch is off? Today the answer is no (D2).

## 6. Suggestions for P4

- **Evidence pack.** Build it from the session stream filtered by the execution's `trace_id`.
  That trace covers every event from `execution.started` to `execution.finished`, and the
  decision and approvals are found by `decision_id`. The evidence schema's `execution.status`
  has no `refused`, `shadowed` or `compensation_failed`. Map them as follows:
  - refused and shadowed → `not_run`
  - compensation_failed → `failed`

  The incident and the shadow flag go into `checks`.
- **Echo binding.** A small in-process binding that prints and remembers the last message is
  enough for the lifecycle demo. The executor already writes observations into state.
