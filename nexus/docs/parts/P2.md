# P2 — Policy engine & gate

**Status:** ready to build · **Estimate:** 2 weeks · **Milestone:** M1 (3 of 5 parts)
**Read first:** `../../GOAL.md`, `../INDUSTRIAL_BLUEPRINT.md` §4.5–4.6, `P1.md`, ADR-0006,
ADR-0008, ADR-0009 (structured envelope), ADR-0011 (cel-python).

## Goal

A deterministic gate: given a proposal, the pack that declares its action, the policy and fresh
world state, it returns ALLOW, DENY or NEEDS_APPROVAL with reasons, and records the decision as an
event. No model is involved, and the same inputs always give the same verdict.

P2 contains **no execution, no approvals inbox, no HTTP and no LLM**.

---

## 0. Hard constraints

The P0 and P1 constraints all still apply. In addition:

1. **Pure core.** `evaluate(...)` is a pure function of (proposal, pack, policy, snapshot, now).
   All I/O (reading state, writing the decision event) lives in `Gate.decide`, around it.
2. **Fail closed.** Any error while deciding (unknown action, bad params, a CEL evaluation error,
   a missing state key) is a DENY with a reason, never an ALLOW and never an exception to the
   caller.
3. **Taint can only tighten.** Context origins can turn ALLOW into NEEDS_APPROVAL; nothing in a
   proposal can turn DENY or NEEDS_APPROVAL into ALLOW.
4. **New dependency:** `cel-python` (ADR-0011). The envelope contract change is ADR-0009.

`nexus validate` gains the semantic rule `CEL_SYNTAX` (every precondition, effect and
compensation param must parse). The CLI gains `nexus kill-switch on|off|status`.

## 2. World state the gate reads

- A pack's state lives under `entity = <pack id>`, one key per observable instance, e.g.
  `oven.zone[2].mode`. Only keys that match a declared observable (`[n]` matches `[*]`) are
  visible to preconditions, converted to the observable's type.
- A value is **stale** when `now − updated_at > max_age_s`. Stale values stay visible, but if a
  precondition reads one the decision is DENY (`STATE_STALE`).
- The kill switch is the state key `(system, kill_switch)`, written with CAS through the event
  store, so turning it on is itself an event and every gate process sees it on its next decision.

## 3. Decision procedure

In this order. Steps 1–4 stop at the first failure; steps 5–8 collect every reason.

| # | Check | Outcome and code |
|---|---|---|
| 1 | Kill switch on | DENY `KILL_SWITCH` |
| 2 | Proposal valid against `proposal.schema.json` | DENY `PROPOSAL_INVALID` |
| 3 | `pack:action` is loaded | DENY `UNKNOWN_ACTION` |
| 4 | Params valid against the action's params schema | DENY `PARAMS_INVALID` |
| 5 | Effective autonomy (action level, capped by the policy) is L0 or L1 | DENY `AUTONOMY_OBSERVE_ONLY` / `AUTONOMY_ADVISE_ONLY` |
| 6 | A param outside `envelope.params` bounds | DENY `ENVELOPE_EXCEEDED` |
| 7 | Rate limit: non-DENY decisions for this action in this session within `per_s` ≥ `max` | DENY `RATE_LIMITED` |
| 8 | Each precondition: reads stale state / reads a missing key / errors / is false | DENY `STATE_STALE` / `STATE_UNKNOWN` / `PRECONDITION_ERROR` / `PRECONDITION_FAILED` |
| 9 | The triggering context item is not `user`/`system`, or there is none; or no context item is `user`/`system` | NEEDS_APPROVAL `TAINTED_TRIGGER` / `NO_TRIGGER` / `TAINTED_CONTEXT`, quoting the ref |
| 10 | Effective autonomy L2 | NEEDS_APPROVAL `AUTONOMY_L2` |
| 11 | Otherwise (L3/L4, low or medium risk, untainted) | ALLOW |

`approvals_required` is the action's `approvers` (default 1; critical actions declare 2) for
NEEDS_APPROVAL and 0 otherwise. The rate limit counts decisions, not executions, because the gate
runs before execution; this is stricter, never looser. Sandboxes are not run in P2.

The decision document is validated against `decision.schema.json` and appended as one event,
type `decision.made`, on stream `session/<session_id>`, with payload
`{proposal, decision, pack: "<id>@<version>"}`. `state_versions` lists the version of every key
a precondition read; `proposal_hash` is `sha256(JCS(proposal))`; `policy_version` is
`<policy name>@<policy version>`.

## 4. API

```python
pack = LoadedPack.from_file("contracts/examples/valid/stf.pack.yaml")  # raises PackError
policy = Policy(name="default", version="0.1.0", max_autonomy={"stf": "L2"})
verdict = evaluate(proposal, packs, policy, snapshot, now)  # pure
gate = Gate(store, packs=[pack], policy=policy)
decision = await gate.decide(proposal)  # -> decision dict, event appended
await gate.set_kill_switch(True, actor, reason="maintenance")
```

## 5. Acceptance — P2 is done when every item passes

| # | Check | Command |
|---|---|---|
| A1 | Lint, format, `make check` | `make check` |
| A2 | `CEL_SYNTAX`: a pack with an unparsable precondition fails `nexus validate` with that code; all valid examples still pass | `pytest tests/test_semantic_rules.py` |
| A3 | Table-driven verdicts: at least one case per row of §3, each asserting outcome, codes and `approvals_required` | `pytest tests/test_gate_table.py` |
| A4 | Stale state: a precondition that reads a value older than `max_age_s` → DENY `STATE_STALE`; the same value fresh → not denied for staleness | `pytest tests/test_gate_table.py` |
| A5 | Taint: a proposal triggered by a `doc` or `tool` item that would otherwise be ALLOW → NEEDS_APPROVAL `TAINTED_TRIGGER` with the ref in the message; taint never upgrades a DENY | `pytest tests/test_gate_table.py` |
| A6 | Fail closed: CEL errors, missing keys and wrong types are DENY, never an exception | `pytest tests/test_gate_table.py tests/test_cel.py` |
| A7 | Determinism: the same inputs give an identical verdict 1000 times; `int` and `double` params give the same verdict | `pytest tests/test_gate_table.py` |
| A8 | Decision events: `decide` appends one valid `decision.made` event whose decision validates against `decision.schema.json`; the chain verifies | `pytest -m integration tests/test_gate_db.py` |
| A9 | Kill switch: `nexus kill-switch on` → every proposal, including ones that were ALLOW, is DENY `KILL_SWITCH`; `off` restores; both are events | `pytest -m integration tests/test_gate_db.py` |
| A10 | Rate limit across decisions in the database | `pytest -m integration tests/test_gate_db.py` |
| A11 | Latency: 10k end-to-end `decide` calls (state read + evaluate + event write), p95 < 50 ms | `uv run python scripts/bench_gate.py` |
| A12 | `make test-db` passes; `git status` lists changes only under `nexus/` | `make test-db` |

## 6. Out of scope (do not build)

Execution, verification, compensation, idempotency (P3) · approvals and their signatures (P3/P4)
· sandbox runs · autonomy promotion and demotion events (later; the policy cap is the only
override) · Cedar or a policy file format (the policy is code until P8) · HTTP (P8) · LLMs.
