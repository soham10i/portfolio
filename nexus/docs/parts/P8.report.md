# P8 report: API, SDKs and the approvals inbox

Date: 2026-10-31. All commands below ran from `nexus/`. Database tests used the local
`deploy/compose.yml` Postgres on :5433 (`NEXUS_DB_URL=postgresql://nexus:nexus@localhost:5433/nexus`).
**No test or CI run calls a real provider.** The API tests drive the planner and answerer with
scripted fakes. The server binds loopback only, and nothing runs in the cloud. Signing keys and
anchor keys are made per run and stay local. Nothing is committed.

Four new decisions:

- ADR-0026: the API's dependencies (FastAPI, uvicorn, websockets, cryptography), all permissive.
- ADR-0027: approvals over HTTP are Ed25519 signatures over the hash the client computed.
- ADR-0028: principals, bearer tokens and session isolation.
- ADR-0029: one entry point with a deterministic ask/act rule.

**Q-P5-1, Q-P5-2 and Q-P7-1 are still open.** The API keeps the conservative defaults: every
model call free, private unless the request says `cloud: true`. One new question, Q-P8-1, is in
§3.

- **New dependencies** (ADR-0026): `fastapi`, `uvicorn`, `websockets`, `cryptography`, and
  `httpx` as dev only. Everything they pull in is MIT, MIT-0, BSD or Apache. The SDKs add none.
- **The licence check is now an allow-list as well as a deny-list.** Every installed package
  must match MIT, BSD, Apache, ISC, PSF or MPL, so a package with an unknown licence fails.
  `cel-python` is the one exception, named in the `Makefile`: its wheel has no licence field, and
  its `LICENSE` file is Apache-2.0 (ADR-0011).

  (`alg`, `key_id`, `public_key`, `value`, `verified`). `set-zone-temp.evidence.json` (valid)

## 2. Design notes

- **An approved item stays in the inbox** until it executes, marked "approved by you", so the
  approver can see it is waiting on the owner.
- **A session owner who is also an approver** can approve planner proposals in their own
  session; only the proposer itself is refused (ADR-0013). In the planner's case the proposer is
  the planner agent, so the owner is not it. Separating the two roles is a policy choice P8
  does not make.
- **Crash recovery** of an execution left `running` is still out of scope (ADR-0012); a
  long-lived server makes it more likely. P13 takes it.
- **TypeScript JCS and big numbers.** JS numbers are doubles, so the TS JCS refuses integers
  beyond 2^53 that print as digits (below 1e21) rather than send a value Python would hash
  differently.

## 3. Flags for the owner

1. **Q-P8-1 (new): must CLI approvals be signed?** Over HTTP every approval is signed. The CLI
   still accepts an unsigned `nexus approve`, as in P3, and the evidence pack shows it as
   unsigned; `--key` signs. Options:
   - keep it, as now (the CLI needs database access, which is already full trust);
   - require `--key` for every approval;
   - require it only for critical actions.

   Not unsafe to default, so P8 ships the first option and records it.
2. **Q-P5-1, Q-P5-2 and Q-P7-1 are still open.** `ask` and `act` are private by default and give
   up rather than fall back to the cloud; `cloud: true` is a per-request opt-in; every call is
   free.
3. **Loopback only, no TLS.** Fine for one machine. Anything else is P13 (OIDC, TLS, rate
   limits).
4. **Nothing is committed.**
