## 1. Memory: current, deleted, purged (ADR-0030)

- Migration `0006_p8_1.sql` adds `deleted_at` and `deleted_reason` to `memories`.
- `delete(id, reason)` marks the row deleted and keeps its text. It records `memory.deleted`
  (id, sha256, reason, `"kept": true`). Deleting a deleted memory is refused.
- Search (what the answerer sees) and `list` skip deleted memories; `list --all` and `show`
  include them, each with `status: current | deleted`.
- `purge(id, reason)` removes the row, current or deleted, and records `memory.purged`
  (id, sha256, reason). Only the hash stays in the chain.
- CLI: `nexus memory delete ID --reason`, `nexus memory purge ID --reason`, `nexus memory list --all`.

## 2. Model caps that adapt (ADR-0031)

Providers stay in config order: Gemini, Groq, Ollama.

- New per-provider config: `requests_per_minute`, `tokens_per_minute`, `quota_timezone`
  (the zone whose midnight resets the daily quota) and `max_wait_s` (how long a call may wait
  for a per-minute window before it moves on to the next provider).
- Values, kept inside the published free-tier limits (checked 2026-10-31):
  - Gemini (`gemini-flash-lite-latest`): Google shows free-tier numbers only in AI Studio;
    public guides put Flash-Lite at about 15 RPM and about 1000 requests a day, reset at
    midnight Pacific. Configured: 10/min, 200/day, 200 000 tokens/min, `America/Los_Angeles`.
  - Groq: `llama-3.3-70b-versatile` is shut down on 2026-08-16; the replacement is
    `openai/gpt-oss-120b` (30 RPM, 1000 RPD, 8000 TPM on the free plan). Configured: 20/min,
    500/day, 6000 tokens/min.
- Adaptive, per process (shared by every router in it, so the API's per-request routers share it):
  - a sliding one-minute window of requests and tokens per provider;
  - on a 429 the effective per-minute limit halves; each success adds one back, up to the
    configured value (additive increase, multiplicative decrease);
  - Groq's `x-ratelimit-remaining-*` and `x-ratelimit-reset-*` headers: no requests left
    means the day is used up; too few tokens left means wait for the token reset;
  - a Gemini 429's `RetryInfo.retryDelay` sets the pause, and a `QuotaFailure` whose quota id
    is per-day marks the day used up.
- A used-up day is stored (`model_usage.exhausted_at`), so another process skips the provider
  too (`model.refused QUOTA_EXHAUSTED`) until the provider's own midnight.
- A per-minute window that frees within `max_wait_s` is waited for (the sleep is injectable);
  otherwise the provider is skipped with `model.refused RATE_LIMITED`.
- `nexus models` shows each provider's limits and today's usage on its own quota day.

## 3. Answers that cover the question, or ask (ADR-0032)

- **Points.** The compose reply lists the points the question asks (1–6). Each sentence names
  the point it answers. A point with no sentence left after the checks and the critic is
  reported as not found in the sources (`uncovered`), never filled in. The critic also reports
  points the answer misses.
- **Dynamic output limit.** The compose call's `max_output_tokens` scales with the number of
  points the question seems to ask and the number of sources (256–1024); the critic's with the
  number of sentences (192–512). The router also waits or moves on when the per-minute token
  window cannot hold the request.
- **Clarifying questions.** Status `clarify`, event `answer.clarify_requested`, with up to 3
  questions. Two ways in:
  - deterministic, with no model call: nothing relevant was found and the question names an
    ambiguous asset (`'zone' could be zone 1 or zone 2`);
  - the model's decision `clarify`, when the sources answer different readings of the question.
  The reply comes back with `clarifies: <answer_id>` (API `MessageIn.clarifies`, CLI
  `--clarifies`), in the same session. Nexus combines the original question with the reply.
  After 2 rounds, `clarify` is no longer offered.

## 4. Learning from ratings (ADR-0033)

- `POST /v1/answers/{answer_id}/rating {"rating": "up" | "down", "note"}`: a human, the owner
  of the answer's session. CLI: `nexus rate ID up|down [--note]`.
- Event `answer.rated`. Only a given answer can be rated.
- 👍 makes the answer a style example (`answer_examples`, scoped to the user); 👎 retires it.
  The latest rating wins.
- The compose prompt shows up to 2 of the user's examples, the most similar first, marked
  "style only, not sources": they are not in the cite enum, so they can never be cited. An
  example built from a memory is shown only to the local model.
- With no ratings, the prompts are the same as without this feature.
