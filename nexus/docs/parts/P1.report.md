## 2. Deviations from the brief

- **D1. The example events had placeholder hashes.** `genesis.event.json` and
  `second.event.json` from P0 carried made-up hashes, so A3 failed as written. They now carry
  `sha256(JCS(event without hash))`, and `second.prev_hash` is genesis's real hash. The two
  invalid examples that reuse the old strings (`ts-no-z`, `prev-hash`) are invalid for other
  reasons and were left alone.
- **D2. Deadlock under 100 concurrent CAS writers on a new key.** The planned lock order was
  "state row, then stream head". A key's first write has no state row to lock, so several first
  writers passed the version check, queued on the stream head, and the later `INSERT … ON
  CONFLICT` waited on a row lock held by a writer that was itself waiting on the stream head.
  Postgres reported the cycle. Fix: `state.set` first takes a transaction advisory lock on
  `jsonb_build_array(schema, entity, key)`, then the stream head. Recorded in ADR-0008,
  decision 5. A hash collision between two keys only serialises them; it cannot create a cycle,
  because every writer still takes exactly one key lock before the stream lock.
- **D3. Test-only lint ignores.** `S311` (seeded `random.Random` in the rebuild test) and
  `S608` (SQL built from the test's own schema name) are ignored under `tests/**` only.

One stream tops out around 1.3k appends/s on a laptop, which is the head-row lock that ADR-0008
predicted. Separate streams scale. That is ample for M1; it matters only if one session ever
needs more than about 1k events per second.

## 5. Suggestions for P2

- P2's decision events should go through `EventStore.append` on the proposal's session stream,
  with the policy version in the payload, so `nexus chain verify` covers them with no new code.
- Freshness (`max_age_s`) can read `StateRow.updated_at`, which is the event's `ts`; it is a
  string in the event's format, so compare parsed times, not strings.
- **Q2 (structured envelope) has to be decided before P2 starts**: the gate checks parameters
  against the envelope, so its shape fixes the CEL bindings and is a contract change (ADR).
- Check `cel-python`'s licence and its dependencies before adding it (it already pulls in
  `lark`, MIT, which is installed).
