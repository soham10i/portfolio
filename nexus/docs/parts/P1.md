# P1 — Event store & world state

**Status:** ready to build · **Estimate:** 1–2 weeks · **Milestone:** M1 (2 of 5 parts)
**Read first:** `../../GOAL.md`, `../INDUSTRIAL_BLUEPRINT.md` §2 (principle 6), §4.1, `P0.md`,
ADR-0003, ADR-0007.

## Goal

One append-only, hash-chained event log in Postgres, and a world-state projection built from it
with compare-and-set writes. Everything later (decisions, approvals, executions, incidents) is
written as events through the one function P1 provides, and state is always a projection that
can be rebuilt from those events.

P1 contains **no HTTP, no models, no gate**. It is a library, a migration and three CLI commands.

---

## 0. Hard constraints

The P0 constraints all still apply (no commits, write only inside `nexus/` plus
`.github/workflows/nexus-ci.yml`, standalone, licence allow-list, Python 3.12, ruff, type hints,
no unmeasured numbers). In addition:

1. **One write path.** Only `EventStore.append` (and `set_state`, which calls the same internal
   function inside one transaction) inserts events. No other module issues `INSERT INTO events`.
2. **Append-only in the database too.** A trigger rejects `UPDATE`, `DELETE` and `TRUNCATE` on
   `events`. The tamper test has to disable it deliberately, the way an attacker with owner rights
   would.
3. **The hash is the contract's hash.** `hash = sha256(JCS(event without "hash"))` exactly as
   `event.schema.json` documents it, with RFC 8785 canonical JSON. No local variant.
4. **New dependency:** `rfc8785` (Apache-2.0, no dependencies), recorded in ADR-0008. `asyncpg`
   moves from a dev to a runtime dependency (ADR-0007 already chose it for P1).

## 2. Data model (`0001_event_store.sql`)

| table | columns | notes |
|---|---|---|
| `events` | `pos` identity PK, `stream`, `seq` (≥ 1), `type`, `payload` json, `actor` json, `ts` text, `trace_id`, `prev_hash` (null only at seq 1), `hash` unique | `UNIQUE (stream, seq)`. `payload` and `actor` are stored as their JCS text in `json` (not `jsonb`) columns, so the bytes that were hashed are the bytes that are read back. `ts` stays text for the same reason. |
| `streams` | `stream` PK, `head_seq`, `head_hash` | One row per stream; locked `FOR UPDATE` by every append, which serialises appends per stream and lets verification detect a deleted tail. |
| `state` | `entity`, `key` (PK together), `value` jsonb, `version` (≥ 1), `updated_at` text, `event_pos` → `events.pos` | The world-state projection. `updated_at` is the `ts` of the event that wrote it; P2 uses it for `max_age_s`. |
| `nexus_migrations` | `version` PK, `applied_at` | Applied migration files. |

A trigger on `events` raises on `UPDATE`, `DELETE` and `TRUNCATE`.

## 3. API

```python
store = await EventStore.connect(url, schema=None)  # asyncpg pool; schema sets search_path
await store.migrate()  # idempotent
ev = await store.append(stream, type, payload, actor, trace_id=None)  # -> validated event dict
events = await store.read(stream, after_seq=0)  # in seq order
report = await store.verify_chain(stream=None)  # all streams when None
row = await store.state.get(entity, key)  # StateRow | None
row = await store.state.set(entity, key, value, expected_version, actor, stream, trace_id=None)
diff = await store.state.check()  # rebuild from events, compare with live
```

- `append` builds the event (`schema_version "1"`, next `seq`, `prev_hash` = stream head, `ts`
  = UTC now with milliseconds and `Z`, `trace_id` generated when absent), **validates it against
  `event.schema.json`** with the P0 validator, hashes it, inserts it and moves the stream head, in
  one transaction.
- `state.set` is compare-and-set: it succeeds only if the current version equals
  `expected_version` (0 = the key must not exist yet). It appends one `state.set` event with
  payload `{entity, key, value, version, prev_version}` and updates the projection in the same
  transaction. On a mismatch it raises `CasConflict(entity, key, expected, actual)` and writes
  nothing.
- `verify_chain` recomputes every hash, checks `prev_hash` links, `seq` = 1, 2, 3 … without gaps,
  and that each stream head equals its last event. It returns
  `ChainReport(ok, events_checked, streams_checked, problems)`, where each problem names
  `stream`, `seq` and a code: `HASH_MISMATCH`, `PREV_HASH_MISMATCH`, `SEQ_GAP`, `HEAD_MISMATCH`.
- `state.check` replays every `state.set` event: for each `(entity, key)`, the event with the
  highest version wins. It returns the differences from the live table (empty when they agree).
  Rebuilding never writes to `events`.

## 4. CLI

`NEXUS_DB_URL` selects the database. `nexus db migrate` exits 0. `nexus chain verify` exits
0 when the chain is intact and 1 with one line per problem (`stream seq CODE message`).
`nexus state check` exits 0 when the projection equals the rebuild, 1 otherwise. All three exit 2
on a usage or connection error.
