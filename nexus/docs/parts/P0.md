# P0 — Contracts & repository

**Status:** ready to build · **Estimate:** 1 week · **Milestone:** M1 (1 of 5 parts)
**Read first:** `../../GOAL.md`, `../INDUSTRIAL_BLUEPRINT.md` §2, §4.2, §4.5, §7.

## Goal

Freeze the shapes every later part builds against, and give the folder a working skeleton:
packaging, lint, tests, CI, a local Postgres with pgvector, and a CLI that validates contracts.
After P0, no later part may invent an interface; it reads it from `contracts/v1/`.

P0 contains **no runtime logic**: no gate, no event store, no HTTP, no LLM.

## 2. The contracts (JSON Schema draft 2020-12)

Every schema has `$schema`, `$id` of the form `https://nexus.local/contracts/v1/<name>.schema.json`
(identifier only, never fetched), `title`, `description`, and `additionalProperties: false` on
every object unless stated. Field descriptions are required: they are the documentation.

### 2.1 `common.schema.json` (`$defs` only)

| def | rule |
|---|---|
| `id_segment` | `^[a-z][a-z0-9_]{0,47}$` |
| `pack_id` | an `id_segment` |
| `action_id` | `^[a-z][a-z0-9_]{0,47}(\.[a-z][a-z0-9_]{0,47}){1,3}$` (e.g. `oven.set_zone_temp`) |
| `qualified_action_id` | `<pack_id>:<action_id>` (e.g. `stf:oven.set_zone_temp`) |
| `semver` | SemVer 2.0 core, `^\d+\.\d+\.\d+(-[0-9A-Za-z.-]+)?$` |
| `uuid` | `format: uuid` and a matching pattern (formats are asserted, see §4) |
| `sha256_hex` | `^[0-9a-f]{64}$` |
| `trace_id` | `^[0-9a-f]{32}$` (W3C trace context) |
| `timestamp` | `format: date-time`, must end in `Z` (UTC only) |
| `risk` | enum `low`, `medium`, `high`, `critical` |
| `autonomy` | enum `L0`, `L1`, `L2`, `L3`, `L4` |
| `actor` | object `{kind: enum human/agent/pack/system, id: string 1..128}` |
| `taint_source` | enum `user`, `system`, `tool`, `doc`, `external` |
| `cel_expr` | string 1..500 (CEL is parsed in P2, not now) |
| `reason` | object `{code: ^[A-Z][A-Z0-9_]{2,47}$, message: string 1..500}` |

### 2.2 `action.schema.json`

Required: `id` (action_id), `title`, `risk`, `params` (a JSON Schema object, see below),
`preconditions` (array of cel_expr, may be empty), `effects` (array of cel_expr, may be empty),
`autonomy` (default `L0` if absent? **no**, it is required, so it is always explicit).
Optional: `description`, `envelope` (object of named numeric limits: `{name: number}`),
`verify_within_s` (integer 1..3600), `compensation` (object `{action: action_id, params: object of
cel_expr}`), `sandbox` (id_segment), `approvers` (integer 1..2), `rate_limit` (`{max: int ≥1,
per_s: int ≥1}`), `idempotent` (boolean, default false).

`params` must itself be `{type: "object", properties: {...}, required: [...],
additionalProperties: false}`; each property must declare `type`. Validate this with a schema, not
by trusting it.

Structural rules expressed in the schema (`if`/`then`):
- `risk ∈ {high, critical}` → `autonomy ∈ {L0, L1, L2}`.
- `risk = critical` → `approvers = 2` required.
- `autonomy ∈ {L3, L4}` → `verify_within_s` and `compensation` required.

### 2.3 `pack-manifest.schema.json`

Required: `schema_version` (const `"1"`), `pack` (pack_id), `version` (semver), `owner`, `title`,
`observables` (array, may be empty), `actions` (array of action, may be empty), `connector`.
Optional: `description`, `sandboxes` (array of `{id: id_segment, description}`), `knowledge`
(array of relative paths), `evals` (array of relative paths), `tags`.

`observables[]`: `{id: ^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*|\[\*\]|\[\d+\])*$, type: enum
number/integer/boolean/string/enum, unit?: string, enum_values?: [string] (required iff type=enum),
max_age_s: integer 1..86400, description}`.

`connector`: `oneOf` by `kind`:
- `python` → `{kind, module: dotted path}`
- `openapi` → `{kind, spec: relative path or https URL, base_url_env: ^[A-Z][A-Z0-9_]*$}`
- `mcp` → `{kind, transport: enum stdio/http, command?: [string], url_env?: env name}`
- `opcua` → `{kind, endpoint_env: env name, namespace: string}`
- `mqtt` → `{kind, broker_env: env name, sparkplug: boolean}`

Secrets never appear in a manifest: only the **name** of an env var that holds them.

### 2.4 `proposal.schema.json`

Required: `proposal_id` (uuid), `session_id` (uuid), `action` (qualified_action_id), `params`
(object), `rationale` (string 1..2000), `context` (array, ≥ 1, of `{source: taint_source, ref:
string 1..256, triggered: boolean}`; `triggered: true` marks the item that prompted the proposal),
`proposer` (actor), `created_at` (timestamp).
Optional: `plan_id` (uuid), `depends_on` (array of uuid), `idempotency_key` (string 8..128).

### 2.5 `decision.schema.json`

Required: `decision_id`, `proposal_id` (uuid), `outcome` (enum `ALLOW`, `DENY`,
`NEEDS_APPROVAL`), `reasons` (array of reason; ≥ 1 when outcome ≠ ALLOW), `approvals_required`
(integer 0..2; must be 0 for ALLOW/DENY, ≥ 1 for NEEDS_APPROVAL), `policy_version` (string
1..64), `autonomy` (autonomy), `state_versions` (object: entity key → integer ≥ 0),
`proposal_hash` (sha256_hex), `latency_ms` (number ≥ 0), `decided_at` (timestamp).

### 2.6 `evidence-pack.schema.json`

Required: `proposal` ($ref proposal), `decision` ($ref decision), `checks` (array of `{name,
passed: boolean, detail?}`), `approvals` (array of `{approver: actor, proposal_hash: sha256_hex,
approved_at: timestamp}`), `execution` (`{status: enum not_run/succeeded/failed/compensated,
idempotency_key?, started_at?, finished_at?, error?: reason}`), `verification` (`{status: enum
not_run/passed/failed/timed_out, observed?: object}`), `event_refs` (array of `{stream, seq}`),
`chain_head` (sha256_hex).
Optional: `simulation` (`{ran: boolean, sandbox?: id_segment, passed?: boolean, summary?: string,
trace_ref?: string}`).

### 2.7 `event.schema.json`

Required: `schema_version` (const `"1"`), `stream` (`^[a-z][a-z0-9_]*(/[a-z0-9_-]+)*$`, e.g.
`session/0b7…`, `pack/stf`), `seq` (integer ≥ 1), `type` (`^[a-z]+(\.[a-z_]+)+$`, e.g.
`proposal.created`, `decision.made`), `payload` (object, `additionalProperties` allowed), `actor`,
`ts` (timestamp), `trace_id`, `prev_hash` (sha256_hex, or null **only** when `seq = 1`), `hash`
(sha256_hex).

Document in the schema description, for P1: `hash = sha256(canonical_json(event without "hash"))`,
where canonical JSON is RFC 8785 (JCS). P0 implements **only** the validation, not the hashing.

### 2.8 Semantic rules (in `validate.py`, beyond what JSON Schema can say)

Each rule has a stable code. Each code is covered by exactly one invalid example and one test.

| code | rule |
|---|---|
| `DUPLICATE_ACTION` | action ids unique within a manifest |
| `DUPLICATE_OBSERVABLE` | observable ids unique within a manifest |
| `UNKNOWN_SANDBOX` | `action.sandbox` names a declared `sandboxes[].id` |
| `UNKNOWN_COMPENSATION` | `compensation.action` names an action in the same manifest |
| `SELF_COMPENSATION_LOOP` | compensation chains must not cycle (A→B→A) |
| `ENVELOPE_PARAM_MISMATCH` | an `envelope` key ending in `_max`/`_min` names a declared param prefix (e.g. `temp_max` ↔ param `temp`) |
| `PATH_ESCAPE` | `knowledge`/`evals`/`openapi.spec` paths are relative and don't contain `..` |
| `APPROVALS_MISMATCH` | decision: NEEDS_APPROVAL with `approvals_required` = 0, or ALLOW/DENY with > 0 |
| `PREV_HASH_RULE` | event: `prev_hash` null iff `seq = 1` |
| `TRIGGER_COUNT` | proposal: at most one `context[]` item has `triggered: true` |

Issue format: `ValidationIssue(code, pointer, message)`, where `pointer` is an RFC 6901 JSON
Pointer. Structural errors from `jsonschema` use code `SCHEMA` with the instance path as pointer.

## 3. Examples

- `examples/valid/`: `echo.pack.yaml` (one `echo.say` action, low risk, L3 with verify +
  compensation, python connector); `stf.pack.yaml` (the four STF actions from the blueprint:
  `order.place` medium, `oven.set_zone_temp` high/L2, `conveyor.set_speed` medium,
  `vgr.sweep_home` low; three observables; `stf_sim` sandbox); `opcua-line.pack.yaml` (opcua
  connector, read-only, no actions); one valid `proposal`, `decision` (each outcome), `evidence-pack`,
  and two `event`s (seq 1 and seq 2).
- `examples/invalid/`: one file per semantic code **plus** at least these structural cases:
  missing `risk`, `high` risk at `L3`, `critical` without `approvers: 2`, L3 without compensation,
  unknown connector kind, bad semver, param without `type`, secret-looking literal in a connector
  (a `*_env` value that is not an env-var name), `ts` without `Z`.
- Each invalid file `X.yaml` has `X.expect.json`: `{"kind": "...", "codes": ["..."]}`. The test
  asserts the exact set of codes, so an example that fails for the wrong reason fails the test.
- File naming: `<name>.<kind>.yaml|json`, where kind ∈ `pack`, `proposal`, `decision`,
  `evidence`, `event`. The CLI infers the kind from that suffix, or takes `--kind`.

## 4. Code

- **`registry.py`**: loads all `contracts/v1/*.schema.json` at import (packaged as package data,
  so it works from an installed wheel), resolves `$ref` through a local `referencing.Registry`
  (no network: a test monkeypatches `socket.socket` to raise).
- **`validate.py`**: `validate(kind: Kind, data: Mapping) -> list[ValidationIssue]` using
  `jsonschema.Draft202012Validator` **with format checking enabled** (`uuid`, `date-time`), then the
  semantic rules. `validate_file(path) -> list[ValidationIssue]` handles YAML (`yaml.safe_load`
  only) and JSON. Issues sorted by pointer, deterministic.
- **`models.py`**: pydantic v2 models for all six kinds (`extra="forbid"`). The JSON Schemas are
  canonical; the models follow them. **Parity test:** every example, valid and invalid, gets the same
  verdict (valid/invalid) from `validate()` and from the pydantic model. Semantic-only cases are
  excluded from pydantic parity and listed explicitly in the test.
- **`cli.py`** (entry point `nexus` in `pyproject.toml`, stdlib `argparse`):
  - `nexus validate <path>... [--kind K] [--json]`: exit 0 if all valid, 1 if any issue, 2 on usage
    or IO error. Human output: `path: CODE pointer: message`, one per line.
  - `nexus schema list`, `nexus schema show <kind>`.
- Dependencies (pin minimum versions, lock with uv): `jsonschema[format-nongpl]`, `referencing`,
  `pydantic>=2`, `pyyaml`. Dev: `pytest`, `ruff`, `pip-licenses`, `psycopg[binary]` (for the DB
  test). Nothing else without a new ADR. `[format-nongpl]` exists precisely to avoid GPL format
  checkers; keep it.

## 6. Local database and CI

- **`deploy/compose.yml`**: one service `db`, image `pgvector/pgvector:pg16` pinned to a specific
  tag (record which in ADR-0003), port `5433:5432` (the portfolio may already use 5432), user/pass/db
  `nexus`, a named volume, and a healthcheck (`pg_isready`). No other services in P0.
- **`tests/test_db.py`** (marked `integration`): connects with `NEXUS_DB_URL`, runs
  `CREATE EXTENSION IF NOT EXISTS vector`, asserts `SELECT '[1,2,3]'::vector` works. Skipped (not
  failed) without the env var.
- **`.github/workflows/nexus-ci.yml`** at the repo root:
  - triggers: `push` and `pull_request` on `main` with `paths: ['nexus/**',
    '.github/workflows/nexus-ci.yml']`
  - `defaults.run.working-directory: nexus`
  - steps: checkout → set up uv + Python 3.12 → `uv sync --frozen` → `ruff check` → `ruff format
    --check` → `pytest -m "not integration"` → `nexus validate contracts/examples/valid` → licence
    check → integration job with a `pgvector/pgvector:pg16` service container running
    `pytest -m integration`
  - pin third-party actions to a full commit SHA, with the version in a comment
  - `permissions: contents: read`
