# NEXUS — Industrial Agentic System Blueprint

**Status:** blueprint v1.0 (2026-10-30). Supersedes the scope of `ARCHITECTURE.md`; keeps its core
idea ("the LLM proposes, the runtime disposes") and its pack model. Where the two differ, this file
says so explicitly (§11).
**Audience:** you, and any AI coding agent building a part. Every part in §8 is self-contained:
inputs, outputs, contracts, tests, and what is out of scope.

> Naming: the portfolio's chat assistant is also called "Nexus". Either make it the first
> client of this runtime (recommended, §9) or rename one of them before Part 6.

---

## 1. The final goal (the north star)

> **One governed agentic runtime that any project, digital or physical, can plug into
> with a manifest instead of code changes. It gives me an assistant that understands every
> project I run and lets agents observe, advise and act on real industrial systems. Every
> action is typed, checked against live state, simulated where possible, approved according
> to risk, verified after execution and recorded in a tamper-evident log. Every claim the
> system makes about itself is backed by a number from a runnable evaluation.**

The goal is reached when **all** of these hold, measured, not asserted:

| # | Criterion | Target | Measured by |
|---|---|---|---|
| G1 | Onboarding a new project | ≤ 1 day, zero core changes, manifest + binding only | onboarding log of 3 real projects |
| G2 | Unapproved high/critical executions | **0**, ever | audit log query in CI + prod |
| G3 | Unsafe-execution rate on the adversarial suite (proposals **generated by the LLM** from attack prompts) | 0 executed, ≥ 300 scenarios | eval harness |
| G4 | False-block rate on legitimate tasks | < 5 % | eval harness, benign suite |
| G5 | Grounded answers (claims supported by a cited source or live-state read) | ≥ 95 %, abstains otherwise | eval harness, judged + spot-checked |
| G6 | Gate decision latency | p95 < 50 ms without sim, < 1 s with sim | OTel traces |
| G7 | Provider outage | user never blocked by one provider; failover < 3 s | chaos test |
| G8 | Traceability | any action → prompt, plan, policy version, state snapshot, approver, result in one query | `nexus trace <action_id>` |
| G9 | Physical-system boundary | agent never writes outside a declared envelope; safety functions stay in the PLC | connector tests against a simulated PLC |
| G10 | Runs offline locally; fits a student cloud budget in production | `docker compose up`, < €30/month | compose smoke test, billing |

**Autonomy target at the goal:** L3 (§4.6) for low/medium actions on simulated systems, L2 for anything
touching physical hardware. Higher levels are earned per action, never assumed.

**Non-goals (forever):** closing real-time control loops; replacing safety PLCs/SIS; acting on an
untrusted instruction; claiming certification (we are *aligned with* standards, not certified).

## 2. Design principles

1. **Contracts first.** Every boundary is a versioned JSON Schema. Code is generated or validated
   against it. An agent building a part reads the contract and never invents an interface.
2. **Deterministic core, probabilistic edge.** Only the planner and the language interface are
   probabilistic. State, policy, gate, execution, audit: plain deterministic code with tests.
3. **Least authority.** Agents hold no credentials. Bindings hold scoped credentials; the kernel
   decides whether a binding may be called.
4. **Data is never instruction.** Anything read from a tool, document, web page, sensor or email is
   *tainted*. Tainted content can inform a plan; it can never authorize or widen one (§4.5).
5. **Earned autonomy.** Every action starts at L0/L1. It is promoted only by evidence (eval scores +
   shadow-mode history), and demoted automatically on an incident.
6. **Everything is an event.** State changes, decisions, model calls, approvals: one append-only event
   stream. Current state is a projection. This gives replay, audit and debugging for free.
7. **Boring technology.** Python 3.12, FastAPI, pydantic v2, Postgres (events, state, pgvector),
   OpenTelemetry. No agent frameworks. Add a dependency only with an ADR.
8. **Measure or mark.** A number in a doc comes from a command, or it reads `TODO(measure)`.

## 3. Industrial context: where the agent sits

The system follows the ISA-95 levels. The agent operates at **levels 3–4** and only
*requests* changes at level 2. It is never inside levels 0–1.

```
L4  Business / ERP        ← agent: plans, reports, scheduling proposals
L3  MES / operations      ← agent: orders, maintenance tickets, recipes (governed actions)
L2  SCADA / HMI           ← agent: setpoint REQUESTS within envelopes, via OPC UA / MQTT
────────────────────────────── hard boundary: nothing agentic below this line ──
L1  PLC / control loops   ← deterministic, interlocks authoritative, rejects out-of-range writes
L0  sensors / actuators
```

Alignment, not certification:
- **IEC 62443**: NEXUS is its own security zone; connectors are the only conduits into OT zones.
- **IEC 61508 / functional safety**: the agent is never part of a safety function. The PLC enforces
  limits even if NEXUS is compromised.
- **EU AI Act Art. 12 & 14**: automatic event logging, plus human oversight with the ability to stop
  (kill switch, §4.5).
- **NIST AI RMF**: the eval harness and risk register map to Measure/Manage.
- **Data models**: OPC UA information models, MQTT Sparkplug B, Asset Administration Shell (AAS)
  for asset descriptions.

## 4. Architecture

```
            ┌──────────────────────── INTERFACES ─────────────────────────┐
            │ chat · voice · approvals inbox · dashboard · CLI · SDK · MCP  │
            └──────────────────────────────┬───────────────────────────────┘
┌──────────────────────────────────────────▼──────────────────────────────────────────┐
│ COGNITION                                                                            │
│  Model Router ── Planner (single loop) ── Critic ── Context Builder                  │
└───────────────┬────────────────────────────────────────────┬────────────────────────┘
                │ proposals (typed)                           │ reads (typed)
┌───────────────▼─────────────── GOVERNANCE (deterministic) ──▼────────────────────────┐
│  Policy Engine · Gate · Simulator hook · Approval service · Autonomy ledger          │
│  Taint tracker · Rate/quota limits · Kill switch                                     │
└───────────────┬──────────────────────────────────────────────────────────────────────┘
                │ authorized commands
┌───────────────▼──────────── EXECUTION ─────────────────┐   ┌──── KNOWLEDGE ─────────┐
│ Executor (idempotent, timeouts, compensation)          │   │ Docs RAG + provenance  │
│ Verifier (did the effect happen?)                      │   │ Asset graph (AAS-like) │
└───────────────┬────────────────────────────────────────┘   │ Memory tiers           │
                │                                             └────────────────────────┘
┌───────────────▼──────────── INTEGRATION ──────────────────────────────────────────────┐
│ Packs = manifest + binding + corpus + evals + (optional) sim                          │
│ Connectors: REST/OpenAPI · MCP servers · OPC UA · MQTT/Sparkplug · SQL · Git/CI ·      │
│ files · calendar/mail (read-only by default)                                          │
└───────────────┬──────────────────────────────────────────────────────────────────────┘
┌───────────────▼──────────── FOUNDATION ───────────────────────────────────────────────┐
│ Event store (append-only, hash-chained) → projections: world state, audit, metrics    │
│ Identity & secrets · OTel traces/metrics · Eval harness · Config/policy versioning    │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.1 Foundation
- **Event store**: one Postgres table, `events(seq, stream, type, payload jsonb, prev_hash, hash,
  ts, actor, trace_id)`. Hash chain per stream. Writes go through one function only.
- **Projections**: world state (`state(entity, key, value, version)` with compare-and-set),
  audit view, metrics. Rebuildable from events; a test rebuilds and diffs.
- **Identity**: humans (OIDC), agents (service identities with a role), packs (scoped credentials in
  Secret Manager, never in prompts). Every event records the actor.

### 4.2 Integration: how "any project" plugs in
A project becomes a **pack** by providing a manifest (`pack.yaml`, JSON-Schema validated):

```yaml
pack: stf
version: 0.3.0
owner: soham
observables:                    # what the agent may READ (state schema)
  - id: oven.zone[*].temp       # typed, with units and freshness
    type: number
    unit: degC
    max_age_s: 5
actions:                        # what the agent may PROPOSE
  - id: oven.set_zone_temp
    risk: high
    params: { zone: {type: integer, minimum: 1, maximum: 3},
              temp: {type: number, minimum: 150, maximum: 240} }
    preconditions: [ "state.oven.zone[params.zone].mode == 'idle'" ]   # CEL expression
    envelope: { temp_rate_max_degC_per_min: 10 }                      # enforced at execution too
    effects:     [ "state.oven.zone[params.zone].setpoint == params.temp" ]  # verified after
    verify_within_s: 120
    compensation: oven.set_zone_temp(zone=params.zone, temp=prev.setpoint)
    sandbox: stf_sim
    autonomy: L2               # starting level; promotion via §4.6
knowledge: [ corpus/ ]          # docs indexed with provenance
evals: [ evals/ ]               # benign + adversarial scenarios
connector: { kind: python, module: stf_nexus.binding }   # or openapi / mcp / opcua / mqtt
```

Adapters that generate packs for you (all start read-only, L0):
- **OpenAPI → pack**: GET endpoints become observables; others become L0 actions to review.
- **MCP server → pack**: any MCP server's tools are wrapped; each tool must be classified
  (read / write + risk) by a human before it can be proposed. MCP is the tool protocol, and the
  NEXUS gate sits between the model and the MCP call.
- **OPC UA browse → pack**: nodes become observables; writable nodes become L0 setpoint actions with
  envelopes taken from the node's EURange.

### 4.3 Knowledge
- **Docs RAG**: hybrid retrieval (BM25 + pgvector) with chunk-level provenance (file, commit, line
  range). Answers must cite chunks; claims without a citation are dropped by the critic.
- **Live grounding**: a question about current values is answered by reading observables, never from
  documents or memory. The answer shows the value, unit and age.
- **Asset graph**: entities and relations (line → oven → zone → sensor), per pack, AAS-style. Lets
  the planner resolve "zone two" to a concrete ID deterministically.
- **Memory tiers**: (1) session episode log; (2) project facts (explicit, user-editable, each with a
  source); (3) user profile/preferences. Nothing is remembered implicitly, and every memory is
  inspectable and deletable.

### 4.4 Cognition
- **Model router**: `generate(task, schema, budget)`; providers pluggable (Gemini, Groq, Anthropic,
  OpenAI-compatible, Ollama). Cooldown on 429, budget per request and per day, structured output with
  schema retry (max 2). Every call is an event (model, tokens, cost, latency).
- **Planner**: one loop (`observe → think → propose plan → receive gate results → revise/finish`),
  max N steps, with a step budget. The plan is a typed DAG of proposals, not free text.
- **Critic**: a separate, cheaper pass that checks the answer/plan against the cited sources and
  live reads, removes unsupported claims, and flags low confidence → abstain.
- **Multi-agent, only when earned**: start with one planner + specialist *tools*. Add role agents
  (e.g. a maintenance agent) only when an eval shows the single planner failing a class of tasks.

### 4.5 Governance (deterministic, the crown jewel)
Lifecycle of every proposal:

```
proposal ─▶ schema check ─▶ taint check ─▶ policy (who may do what, when)
        ─▶ preconditions on FRESH state ─▶ envelope check ─▶ sandbox sim (if declared)
        ─▶ autonomy level → ALLOW | NEEDS_APPROVAL(1 or 2 people) | DENY(reasons)
        ─▶ execute (idempotency key, timeout) ─▶ verify effects ─▶ compensate on failure
        ─▶ evidence pack + events
```

- **Policy engine**: CEL for preconditions and envelopes (side-effect-free, terminates); Cedar or a
  small role/attribute table for "who may approve what". Policies are versioned; each decision
  records the policy version.
- **Taint tracking**: every context item carries an origin (`user`, `system`, `tool`, `doc`,
  `external`). A proposal whose parameters are derived *only* from tainted content, or which was
  triggered by an instruction found in tainted content, is forced to NEEDS_APPROVAL with the source
  quoted. That is the core prompt-injection defense.
- **Approvals**: an inbox with the evidence pack (what, why, sim result, diff of state). Approvals are
  signed (user id + hash of the exact proposal). Approving one proposal never approves a different one.
  Critical actions need two people.
- **Kill switch**: one call sets the system to read-only immediately (all packs, all sessions). It is
  tested in CI.
- **Limits**: rate limits per action, per pack and per session; daily cost budget per provider.

### 4.6 Autonomy ladder (per action, per pack)

| Level | Name | Behaviour | Promotion evidence required |
|---|---|---|---|
| L0 | Observe | can read only | — |
| L1 | Advise | suggests in text, cannot propose | manifest reviewed |
| L2 | Propose | proposes; every execution needs approval | ≥ 50 benign evals pass, adversarial suite 0 unsafe |
| L3 | Act within envelope | executes low/medium inside the envelope, notifies, can be undone | ≥ 30 days shadow mode with ≥ 98 % agreement with human decisions, verify + compensation tested |
| L4 | Exception-only | executes, humans review exceptions | **not used for physical systems** in this project |

Every promotion is an event with its evidence attached. An incident (verify failure, user override,
red-team hit) demotes the action one level automatically.

### 4.7 Execution
- Idempotency key per proposal; retries are safe.
- Timeouts per action; a failed verification triggers compensation and an incident event.
- **Shadow mode**: the planner proposes, the gate decides, nothing executes; the decision is compared
  with what the human actually did. This is the data source for L3 promotion.

### 4.8 Interfaces
REST + WebSocket API, Python and TS SDKs, CLI (`nexus ask`, `nexus trace`, `nexus approve`), an
approvals inbox UI, voice (TTS/STT adapters, local Kokoro / hosted ElevenLabs), and an **MCP server
face**: NEXUS itself can be used from Claude Code or other MCP clients as a governed toolset.

### 4.9 Observability and evaluation
- OTel trace per request: retrieval → model calls → gate → execution → verify.
- **Eval harness**: suites per pack. `benign/` (should succeed), `adversarial/` (attack prompts; the
  LLM generates the proposals, the gate must stop them), `grounding/` (answer vs. abstain), `chaos/`
  (provider down, stale state, connector timeout). Output: `metrics.json`, compared with the last
  baseline in CI. A regression fails the build.

## 5. Your assistant on top of the runtime

The personal assistant is not a separate system. It is **the planner plus an `assistant` pack set**:

| Pack | Observables (read) | Actions (start level) |
|---|---|---|
| `dev` | repos, branches, CI runs, issues, PRs (GitHub API / MCP) | open issue (L2), open PR from a branch (L2), never push to main |
| `portfolio` | site health, deploy status, analytics, chat logs (anonymised) | update project data file (L2), trigger staging deploy (L2) |
| `stf` | factory sim/twin state | §4.2 actions |
| `wind` | telemetry, anomaly scores | create inspection ticket (L2), ack alert (L2) |
| `vision` | scene summaries | annotate/escalate (L2), no actuation |
| `research` | papers/notes corpus | none (read-only) |

"What happened across my projects this week, and what should I do next?" becomes: read observables
across packs → cite sources → propose actions → you approve in the inbox.

## 6. Technology choices (each one gets an ADR)

| Concern | Choice | Why |
|---|---|---|
| Language/service | Python 3.12, FastAPI, pydantic v2 | ML ecosystem, typed contracts |

| Local models | Ollama; Kokoro TTS | offline dev |
| Deploy | Docker, Cloud Run (API), Supabase/Cloud SQL | fits the budget |

## 7. How we build without hallucinating

Rules for every part, human or AI-built:

1. **Spec before code.** Each part starts with `docs/parts/PXX.md` (copy of the part from §8) and
   frozen JSON Schemas in `contracts/`. Changing a contract requires an ADR.
2. **Tests define done.** The acceptance tests are written first and must fail before the code exists.
3. **No unverifiable claims.** Reports list commands run and their output. "It works" without output
   does not count. Numbers without a command are `TODO(measure)`.
4. **Small vertical slices.** A part is ≤ 2 weeks and ends in a demo script that runs from a clean clone.
5. **Out of scope is explicit.** Each part lists what it must *not* build, so agents don't over-build.
6. **Unknowns are logged, not guessed.** An agent that hits an unknown writes it to
   `docs/OPEN_QUESTIONS.md` and stops that sub-task.
7. **Human checkpoints.** You review and commit at the end of each part. Agents never commit or push.

## 8. The parts (build order)

Each part: **Goal → Deliverables → Acceptance (tests) → Out of scope.** Durations are for one
person working part-time with AI assistance, and they are estimates.

### Track A: the governed core

**P0 Contracts & repo** (1 wk)
- Deliverables: repo layout, `contracts/` (pack manifest, action, proposal, decision, evidence pack,
  event), ADR-0001..0005, CI (ruff, pytest, schema validation), `docker compose` with Postgres.
- Acceptance: example manifests validate; an invalid manifest fails with a precise error; CI green.
- Out of scope: any runtime logic.

**P1 Event store & world state** (1–2 wk)
- Deliverables: append API, hash chain, projections, compare-and-set state, `verify_chain`, rebuild.
- Acceptance: tamper test (flip a byte → verification fails); rebuild-from-events equals the live
  projection; concurrent CAS test (100 writers, no lost updates).
- Out of scope: HTTP, models.

**P2 Policy engine & gate** (2 wk)
- Deliverables: CEL preconditions/envelopes, risk routing, autonomy levels, taint rules, kill switch,
  decision events with policy version.
- Acceptance: table-driven tests for ALLOW/DENY/NEEDS_APPROVAL; stale-state test (state older than
  `max_age_s` → DENY); tainted-trigger test → NEEDS_APPROVAL; kill switch → all DENY; gate p95 < 50 ms
  over 10k decisions.
- Out of scope: execution, LLMs.

**P3 Executor, verifier, compensation** (1–2 wk)
- Deliverables: idempotent execution, timeouts, effect verification, compensation, incidents, shadow
  mode.
- Acceptance: duplicate-submit runs once; injected binding failure → compensation → incident event;
  shadow mode executes nothing (binding mock asserts zero calls).
- Out of scope: real connectors (mock binding only).

**P4 Echo pack + lifecycle demo** (0.5 wk)
- Acceptance: `scripts/demo_lifecycle.py` from a clean clone shows ALLOW, DENY, NEEDS_APPROVAL →
  approve → execute → verify → `nexus trace` output.

### Track B: intelligence

**P5 Model router** (1 wk)
- Acceptance: mocked 429 on provider A → B answers with a failover note; schema-invalid output retried
  ≤ 2 times then a clean error; budget exceeded → refusal event; all calls appear as events.
- Out of scope: planning.

**P6 Planner + critic** (2 wk)
- Deliverables: single-loop planner producing typed plans; critic pass; abstention.
- Acceptance: on the echo + a toy pack, 30 benign tasks reach the right proposals (≥ 90 %, measured);
  10 unanswerable questions → abstain (≥ 9/10); step budget enforced.
- Out of scope: multi-agent.

**P7 Knowledge & memory** (2 wk)
- Deliverables: hybrid RAG with provenance, live-read grounding, asset graph, memory tiers with
  inspect/delete.
- Acceptance: every answer sentence maps to a citation or a live read (checked automatically on the
  grounding suite); entity resolution ("zone two" → `oven.zone[2]`) deterministic on 50 cases;
  memory delete removes it from retrieval.

### Track C: surfaces

**P8 API, SDK, approvals inbox** (2 wk)
- Deliverables: REST/WS, session isolation, Python + TS SDK, inbox UI showing evidence packs, signed
  approvals, CLI.
- Acceptance: two-session isolation test; approval of a modified proposal is rejected (hash
  mismatch); P4 demo runs over HTTP.

**P9 Eval harness v1** (1 wk, then continuous)
- Deliverables: benign / adversarial / grounding / chaos suites, `metrics.json`, CI baseline gate.
- Acceptance: a deliberately weakened policy fails CI; metrics reproduce within tolerance across 3 runs.

### Track D: first real domains

**P10 STF pack (simulated factory)** (2–3 wk)
- Deliverables: manifest, binding to the STF sim, sandbox = sim step 30 virtual s, corpus, evals.
- Acceptance: the voice demo "set zone two to 240 °C" → NEEDS_APPROVAL → approve → sim executes →
  verified → spoken confirmation; adversarial STF suite 0 unsafe executions.

**P11 Industrial connectors (OPC UA / MQTT)** (2–3 wk)
- Deliverables: OPC UA and Sparkplug connectors, browse → draft pack, envelope enforcement at the
  connector, a simulated PLC that also enforces its own limits.
- Acceptance: write outside the envelope is blocked by NEXUS **and** by the PLC (defense in depth,
  both tested independently); connector loss → state goes stale → actions DENY.

**P12 Assistant packs (`dev`, `portfolio`)** (2 wk)
- Deliverables: GitHub/MCP-based `dev` pack, `portfolio` pack, a weekly briefing.
- Acceptance: briefing claims all cite a source; "push to main" is not an available action; prompt
  injection planted in an issue body cannot trigger an action (adversarial test).

### Track E: production hardening

**P13 Security & ops** (2 wk)
- Deliverables: OIDC, scoped secrets, threat model (STRIDE per zone), rate limits, backups, restore
  drill, Cloud Run deploy (staging locked, prod public demo with sandboxed sessions).
- Acceptance: restore from backup passes `verify_chain`; pen-test checklist; budget alerts set.

**P14 Autonomy promotion & incidents** (1–2 wk)
- Deliverables: shadow-mode comparison reports, promotion/demotion workflow, incident review page.
- Acceptance: an action is promoted L2→L3 only with attached evidence; an injected incident demotes it.

### Track F: breadth

**P15 Wind PdM pack** and **P16 Vision pack** (2–3 wk each): read-mostly packs proving G1
(onboarding in ≤ 1 day once the core is stable). Record the onboarding time honestly.

**P17 Portfolio integration & public demo** (1 wk): see §9.

## 9. Portfolio integration

- The portfolio's Express backend proxies `/api/nexus/*` to nexusd with a server-side key, so the
  browser only talks to the portfolio's own origin and the CSP stays `connect-src 'self'`.
- The existing "Nexus" chat becomes the first client: Q&A about the portfolio through the `portfolio`
  pack (read-only, L1) from M2 on.
- A `/nexus` demo page shows the lifecycle live against a **per-visitor sandboxed STF sim**:
  proposal → gate → approval → execution → evidence → audit entry. Public visitors can only approve
  actions in their own sandbox. No public path ever reaches a real connector.
- A metrics page renders the latest `metrics.json` from CI (G2–G7), so every public claim links to
  its measurement.

## 10. Risks and how they are handled

| Risk | Mitigation |
|---|---|
| Scope explosion | milestones are stop points; tracks E–F wait until M3 is shown |
| LLM cost on a public demo | per-session token cap, daily budget, recorded replay fallback |
| Prompt injection via docs/issues/sensors | taint tracking (§4.5) + adversarial suite in CI |
| Stale or wrong state → wrong action | `max_age_s` on observables, CAS, verify + compensation |
| Overclaiming industrial readiness | "aligned with", never "compliant"; PLC limits always authoritative |
| Framework/model churn | contracts + router abstraction; no agent framework lock-in |
| Agent-built code drifting from spec | §7 rules: schemas frozen, tests first, outputs in every report |

## 11. Differences from `ARCHITECTURE.md` / `BUILD_BRIEF.md`

1. **Event-sourced foundation** instead of a separate audit log: audit, state and replay come from one
   stream.
2. **Autonomy ladder + shadow mode** added; risk tier alone no longer decides execution.
3. **Taint tracking** added as the explicit prompt-injection defense.
4. **Adversarial evals use LLM-generated proposals.** A 100 % block rate on hand-written bad proposals
   only tests the rule checker, so G3 measures the whole system instead.
5. **Industrial connectors (OPC UA/MQTT) and the ISA-95 boundary** are first-class (P11); the original
   plan had only the STF sim.
6. **MCP** is used as a connector and exposed as an interface; the gate sits between model and tool.
7. **Commit rule made consistent:** agents never commit, including the scaffold; you commit.
8. **CEL** replaces the hand-written precondition DSL (deterministic, well-specified, already exists).
